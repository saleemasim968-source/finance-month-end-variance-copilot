Keystone Close takes cost reports from every site, whatever their layout, language, unit or currency. It reconciles them into one view, separates producing less from spending more, and drafts commentary in which every number is checked against the data before a controller signs off.

The platform

One command from raw exports to reviewed commentary.

Four steps run in sequence. Each one leaves evidence you can open, check and trace back to a line in a source file.

01 · Harmonise

Three layouts in, one structure out.

Files load unchanged. Periods, thousands, decimal commas and ringgit are converted in SQL. Maintained mapping tables put every row on the group chart of accounts, and the local codes stay beside it.

02 · Check

Reconciled to the cent.

Duplicates, missing actuals and unmapped codes are reported with file and line. An unmapped code stops the run.

03 · Analyse

Volume or spending?

A flexed budget splits every variance into what moved with wafer output and what was spent above it.

04 · Explain

Every figure in the draft is checked.

The commentary is written from the calculated figures only. Any number that isn't in the data is rejected. The cost-centre owner adds the cause, and a controller approves.

Controls

The model writes words.
The pipeline owns the numbers.

Generative AI speeds up commentary, but finance can't accept a figure nobody can trace. These controls run on every draft, whether a language model or the built-in template wrote it.

  1. 01

    Number check

    Every figure in a draft must match the calculated data. If not, the draft is rejected, rewritten once, then replaced by the template.

  2. 02

    Human sign-off

    Nothing is released without a controller's approval, recorded with role and time. Approved text is locked.

  3. 03

    Data minimisation

    Only rounded, aggregated figures for one item reach the model. There is no person-level data anywhere.

  4. 04

    Full lineage

    Every reported figure points to its source file and line. Every prompt, answer and check is logged.

  5. 05

    Works offline

    Without an AI key, a template drafts the commentary, and every other control still applies.

Questions

Asked by every finance team.

Is any of our data sent to an AI model?

Only the rounded, aggregated figures of one flagged item, such as "spend effect EUR 477k", and only when an API key is configured. Raw files, rows and names never leave the machine. Without a key, nothing is sent at all.

What if the AI writes a wrong number?

The draft is rejected automatically. It is rewritten once with feedback; if it fails again, a template text is used. A text with an unchecked figure cannot be approved.

Can we change the thresholds and the cost assumptions?

Yes. Materiality thresholds are in one configuration file, and the share of each cost type that moves with volume is in one reference table. Both are applied on the next run.

Do the sites lose their own account structure?

No. Every row keeps its local account and cost-centre code beside the group codes, so each site still recognises its data.

How does this move to our data platform?

The transformations are plain SQL, and the mappings are tables. Both can move to a central platform or be rebuilt in a low-code tool such as KNIME. A parity check is included.

Is this real company data?

No. This is an independent portfolio prototype. Every site, figure and stakeholder is synthetic.
